# GL1TCH Paid Agent API (x402) — Revenue System Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** AI agents pay GL1TCH per call in USDC (x402), with no signup, and the money lands straight in a founder-owned wallet. Every payment shows up on a public ledger that links to its on-chain tx.

**Architecture:** Three new paid Next.js routes under `/api/x402/*` wrap existing scan, agent and deployer logic with `withX402` from `@x402/next`. The PayAI facilitator verifies and settles the client-signed USDC transfer; settlement only happens when the handler returns < 400. An `onAfterSettle` hook posts each settlement to a new revenue store on the bot (Oracle), next to the scan counter. `/revenue` renders that ledger. Bazaar discovery metadata on each route gets us listed in x402 catalogs after the first settlement.

**Tech Stack:** Next.js 16.4 App Router (Node runtime), TypeScript, vitest; `@x402/core` `@x402/next` `@x402/svm` `@x402/evm` `@x402/extensions` 2.28.0, `@payai/facilitator` 2.4.6, `@solana/kit` (peer of `@x402/svm`); bot: Node + tsx, vitest.

**Spec:** this document, §Design (no separate spec; the founder asked for one plan file).

## Design

**Money flow:** agent → `GET /api/x402/scan?mint=…` → `402` with `PAYMENT-REQUIRED` (accepts: Solana USDC + Base USDC, `payTo` = founder wallet) → agent signs a USDC transfer → retries with `PAYMENT-SIGNATURE` → `withX402` asks PayAI `/verify` → handler runs → if status < 400, PayAI `/settle` broadcasts the transfer (PayAI pays the network fee) → `PAYMENT-RESPONSE` header carries the tx → `onAfterSettle` → bot `/revenue/record`.

**Access modes (per request, in order):**
1. No `payTo` configured → `503 {"error":"paid API not configured"}`. Never a 402 with empty `accepts`.
2. Per-IP rate limit (120/min) exceeded → `429`, before any payment.
3. Valid `x-gl1tch-key` → handler runs free, limited to the key's tier rate (`checkApiKey`). Response header `x-gl1tch-access: holder`.
4. Otherwise → `withX402(handler, routeConfig, server)`.

Input is validated **inside the handler**, never before the challenge. x402scan probes without query parameters and fails a route that answers 400 before 402 (its `docs/DISCOVERY.md`, "Common Failure Reasons"). A paid request with bad input reaches the handler, gets 400, and is never settled, so it still costs nothing.

**Discovery:** each 402 carries the bazaar extension (input schema + output example). `/openapi.json` lists the paid operations with `x-payment-info` (`protocols: ["x402"]`, `price: { mode: "fixed", currency: "USD", amount }`) and a `402` response; `/.well-known/x402` lists the three resource URLs (compatibility). Check with `npx -y @agentcash/discovery <origin> -v`.

**Facilitator:** PayAI (`facilitator.payai.network`). Mainnet Solana and Base `exact` with no API key. Each receiving wallet gets 1,000 free settlements for its lifetime; after that, about $0.00133 per Solana settlement (live `/pricing`, 2026-10-27). At $0.01 that keeps ~87% margin. Past the free allowance PayAI needs credits; that's in the risk register (Task 9).

**Rejected or deferred:**
- `@x402/paywall` (browser pay UI) is rejected: it pulls Algorand/WalletConnect stacks, and C: has ~4 GB free.
- Coinbase CDP facilitator / CDP Bazaar is deferred: it needs a CDP API key from the founder. Next plan.
- MCP server, Telegram Stars "Pro" and hardware-wallet affiliate links are separate plans (see end).
